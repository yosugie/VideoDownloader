# VideoDownloader

Рабочая память для ассистента. Файл читается в начале каждой сессии,
чтобы понять контекст проекта и принятые решения, не восстанавливая их
заново из кода и старых разговоров.

## Кто пользователь / контекст

- Соло-разработчик, без команды и без ревью со стороны. Это его первый
  телеграм-бот; с терминалом, git и Linux знаком поверхностно, поэтому
  команды нужно давать целиком и по одной, а не намёками.
- С ассистентом общается по-русски. Код, коммиты и имена в коде — на
  английском.
- Работает в основной ветке `main`, без feature-веток.
- Рабочая машина — macOS, бот живёт на небольшом VPS под Ubuntu. Сервер
  не выделен под бота: на нём уже работает другая служба, и она важнее.
  Отсюда ограничения по памяти, процессору и каналу в юните systemd.
- Просит не гадать, а проверять. По ходу проекта три ошибки были найдены
  именно так: сначала подробный вывод, потом вывод, а не наоборот.

## Что делает бот

Принимает ссылку на YouTube, Instagram или TikTok и присылает файл в
чат. Выбирать формат не нужно: есть видео — приходит видео, фотопост —
приходят картинки. Звук отдельно забирается командой `/mp3`.

Доступ выдаётся по заявке. Незнакомый человек на `/start` видит кнопку
«Отправить заявку», владелец получает её с кнопками «Принять» и
«Отклонить» и ссылкой на профиль; решение приходит человеку ответом.
Сверх этого действует суточный лимит на человека. Владелец видит
статистику, список сбоев и заявки командами, скрытыми от остальных.

## Как это устроено технически

- **aiogram 3**, long polling, зависимости раздаются через
  `workflow_data` диспетчера.
- **yt-dlp** за видео и звуком, **gallery-dl** за картинками: yt-dlp
  умеет только видео и выбрасывает из карусели Instagram всё, где
  `is_video` не истина.
- **curl-cffi** обязателен. Без него yt-dlp не может притвориться
  браузером, а TikTok отдаёт страницу-проверку вместо видео и падает с
  невнятным `Unexpected response from webpage request`.
- **ffmpeg** склеивает видео со звуком и приводит его к H.264. Telegram
  не играет VP9 и AV1 — показывает замерший первый кадр со звуком.
- **SQLite** для учёта загрузок и для списка допущенных людей. Отдельная
  СУБД ради нескольких тысяч строк избыточна. Файлы разные: `stats.db`
  переживёт чистку, а `access.db` терять нельзя — в нём доступ.

### Решения, которые легко сломать по незнанию

- **Имя зависимости `state` занимать нельзя.** aiogram кладёт туда
  `FSMContext` на каждом событии и затирает чужое значение. Переключатель
  паузы называется `runtime`. Тест в `tests/test_startup.py` сверяет
  имена с занятыми.
- **Признаки ошибок ищутся длинными формулировками.** Короткая подстрока
  `"429"` совпадала с цифрами внутри девятнадцатизначных номеров роликов
  TikTok, и любая ошибка выглядела как требование авторизации.
- **Потолок качества считается по высоте кадра.** У вертикальных роликов
  высота — длинная сторона, поэтому значение 720 превращает кадр
  1080x1920 в 405x720. Понижать потолок не стоит.
- **Фильтры по размеру встроены в выбор формата.** Без них бот качал
  файл целиком, убеждался, что тот не влезает в лимит Telegram, удалял
  его и качал заново ступенью ниже.
- **Базы данных в репозиторий не попадают.** Однажды тестовая `stats.db`
  попала в коммит и заблокировала обновление на сервере.
- **Список допущенных спрашивается на каждом событии, а не при запуске.**
  Иначе принятая заявка начинала бы действовать только после
  перезапуска, а ради этого её и заводили.
- **Гостю позволены ровно два действия** (`_is_guest_action`): команда
  `/start` и нажатие кнопки заявки. Расширять этот список нельзя —
  заявка перестанет быть входом. Обработчик гостя отличает по признаку
  `is_member`, который middleware кладёт в данные.
- **Посев из настроек не воскрешает заблокированных** (`Registry.seed`).
  Запись, которая уже есть, не трогается: иначе заблокированный
  владельцем человек возвращался бы в строй при каждом запуске.
- **Заявки принимает тот, кто указан в `ADMIN_IDS`.** Без него принимать
  их некому, и бот работает по-старому — по списку из настроек.

## Как запустить

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # вписать BOT_TOKEN
python -m bot
```

Нужен Python 3.11+ и ffmpeg. Установка на сервер описана в `DEPLOY.md`,
настройки — в `README.md`.

## Известные недочёты / ограничения

- Instagram почти всё отдаёт только авторизованным; без cookies работает
  лишь часть ссылок.
- Суточный лимит живёт в памяти процесса и обнуляется при перезапуске.
- Заявку показываем всем администраторам сразу, и решить может любой;
  кто решил, видно только в базе, в сообщении этого нет.
- Ограничения Telegram на частоту отправки не обрабатываются: при
  сильном наплыве часть сообщений может потеряться.
- Обычный Bot API не принимает файлы больше 50 МБ. Снимается только
  своим Bot API server.

## Правила коммитов git

Упрощённая версия Conventional Commits (не полная спецификация) — набор
правил для соло-проекта без CI/CD и автоматического версионирования.

**Главный принцип:** весь коммит целиком — тип, scope, заголовок, тело —
пишется на английском. Единственное исключение — слова и термины, взятые
прямо из программы (название кнопки, поля, столбца и т.п. на русском) —
они вставляются как есть, но в кавычках `""`.

1. Заголовок — на английском, формат `тип: краткое описание`, тип с
   маленькой буквы, в повелительном наклонении, простым понятным
   английским без сложных технических терминов, в пределах ~72 символов,
   без точки в конце.
2. Русские слова, встречающиеся в заголовке или теле — в кавычках, всё
   остальное вокруг них — на английском.
3. Тело — на английском, 1-2 коротких предложения, только ЧТО изменено,
   без «зачем/почему». Перенос строки примерно на 72 символах.
4. Никаких footer'ов и подписей: без Co-Authored-By, без ссылок на чат
   или сессию — коммит заканчивается сразу после тела.
5. Поле Author не трогаем — остаётся таким, каким его выставляет среда.
6. Один коммит = одно осмысленное законченное изменение.
7. Scope — используем: короткое английское слово в скобках сразу после
   типа. В этом проекте — `config`, `links`, `downloader`, `photos`,
   `stats`, `bot`, `access`, `deploy`. Если изменение общее, scope можно
   не указывать.
8. `!` и footer'ы (Refs/Closes) не используем.

Типы: `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`,
`build`, `ci`, `chore`, `revert` — всегда с маленькой буквы.

Чего в коммите быть не должно: подписей, названия модели или чата,
рассуждений «зачем», двух разных правок, хвастовства (`improve`,
`better`, `properly`), ссылок на задачу или сообщение пользователя.

## Как вести этот файл

Обновлять в том же коммите, который меняет описанное здесь поведение или
решение. Личные данные сюда не попадают: репозиторий открытый, поэтому
ни адресов серверов, ни токенов, ни идентификаторов в примерах.

## Как продолжать работу

незнанию»: каждый пункт там стоил отдельной поломки у пользователя.
