# 🎬 VideoDownloader Bot

Телеграм-бот, который скачивает видео и фото по ссылке из **YouTube**, **Instagram** и **TikTok**.
Присылаешь ссылку — бот сам разбирается, что в посте, и отдаёт готовый файл в чат.
Выбирать формат не нужно: есть видео — придёт видео, фотокарусель — придут картинки.

Написан на Python 3.11+ с [aiogram 3](https://docs.aiogram.dev/) и [yt-dlp](https://github.com/yt-dlp/yt-dlp).

---

## Возможности

| Что | Как это работает |
|---|---|
| 🎬 Видео | Скачивает в MP4 и сам подбирает качество под лимит Telegram |
| 🖼 Фото | Карусели Instagram и слайдшоу TikTok приходят альбомом |
| 🎵 Аудио | По команде `/mp3` вытаскивает звук (192/128/96 kbps) |
| 📊 Прогресс | Живой индикатор: проценты, объём, скорость, оставшееся время |
| 🔒 Доступ | По заявке с подтверждением владельца, плюс чёрный список и суточный лимит |
| 📊 Учёт | Статистика загрузок в SQLite и команда `/stats` для владельца |
| ⏱ Антиспам | Пауза между запросами + очередь одновременных загрузок |
| 🖼 Превью | Обложка и метаданные, чтобы видео нормально выглядело в чате |
| ▶️ Совместимость | Видео приводится к H.264/AAC с faststart — Telegram играет такое везде |
| 🐳 Docker | Запуск одной командой |

### Откуда берутся фотографии

yt-dlp умеет только видео: из карусели Instagram он выбрасывает все узлы, где
`is_video` не истина, а слайдшоу TikTok отдаёт одной звуковой дорожкой. Поэтому
за картинками бот ходит вторым инструментом — [gallery-dl](https://github.com/mikf/gallery-dl),
и запускает его отдельным процессом. Если видеодорожки в посте нет, бот молча
переключается на картинки и присылает их альбомом (до 10 штук — лимит Telegram).

### Почему в зависимостях curl-cffi

TikTok на обычный запрос отдаёт не видео, а страницу-проверку на несколько
сотен байт. Пройти её можно, только если запрос выглядит как запрос настоящего
браузера — вплоть до особенностей TLS-рукопожатия. yt-dlp это умеет, но ему
нужна библиотека `curl-cffi`; без неё в подробном выводе видно:

```
WARNING: [TikTok] The extractor is attempting impersonation,
         but no impersonate target is available
[debug] [TikTok] Webpage size: 537 bytes
ERROR: Unexpected response from webpage request
```

Сообщение невнятное и выглядит как поломка сервиса, хотя на деле не хватает
зависимости. Поэтому она в `requirements.txt`, а бот при запуске предупреждает,
если её нет. YouTube и Instagram работают и без неё.

### Как бот справляется с лимитом 50 МБ

Обычный Bot API разрешает боту отправлять файлы не больше **50 МБ**. Вместо того чтобы
сдаваться на тяжёлых роликах, бот спускается по «лестнице качества»:

```
1080p → 720p → 480p → 360p → worst
```

Он скачивает, проверяет размер готового файла и, если тот не влез, пробует качество ниже.
Если не помогло даже минимальное — предлагает кнопкой забрать только звук.
Нужны файлы до 2 ГБ? Поднимите [свой Bot API server](https://core.telegram.org/bots/api#using-a-local-bot-api-server)
и укажите `TELEGRAM_API_BASE_URL`.

## Быстрый старт

### 1. Создайте бота

Напишите [@BotFather](https://t.me/BotFather) → `/newbot` → придумайте имя →
получите токен вида `123456789:AAE...`.

### 2. Установите зависимости

Нужен **Python 3.11+** и **ffmpeg** (без него не склеить видео со звуком и не сделать MP3):

```bash
# Linux (Debian/Ubuntu)
sudo apt install python3 python3-pip ffmpeg

# macOS
brew install python ffmpeg

# Windows: winget install Gyan.FFmpeg
```

Дальше:

```bash
git clone https://github.com/yosugie/VideoDownloader.git
cd VideoDownloader

python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

pip install -r requirements.txt
```

### 3. Настройте

```bash
cp .env.example .env
```

Откройте `.env` и впишите минимум две вещи:

```env
BOT_TOKEN=123456789:AAE...
ALLOWED_USER_IDS=123456789
```

Свой Telegram ID можно узнать так: запустите бота, напишите ему `/id` — он ответит номером.
Впишите его в `ALLOWED_USER_IDS` и перезапустите. Несколько человек — через запятую:

```env
ALLOWED_USER_IDS=123456789,987654321,555000111
```

> ⚠️ Если `ALLOWED_USER_IDS` оставить пустым, бот будет отвечать **кому угодно**, кто его найдёт,
> и качать видео за ваш счёт трафика. Для личного бота всегда заполняйте белый список.

### 4. Запустите

```bash
python -m bot
```

В логах появится `VideoDownloader 1.0.0 запущен как @ваш_бот`. Можно писать боту в Telegram.

## Instagram и cookies

### Зачем это вообще нужно

HTTP не помнит, кто вы: каждый запрос приходит на сервер как с чистого листа.
Чтобы сайт узнавал вас между запросами, при входе он выдаёт браузеру **cookie** —
короткую строку вроде `sessionid=...`, которую браузер прикладывает к каждому
следующему запросу. Это пропуск, а не пароль: предъявили на входе — вас узнали.

Instagram почти всё содержимое отдаёт только по такому пропуску — даже публичные
посты крупных изданий. Бот приходит без него, Instagram не узнаёт запрос и
отвечает пустотой. YouTube и TikTok в большинстве случаев работают анонимно,
так что cookies нужны в первую очередь ради Instagram.

Пропуск предъявляет **сам бот**, один на всех. Пользователю входить никуда не
нужно: он просто присылает ссылку, а бот обращается к Instagram от имени того
аккаунта, чьи cookies ему дали.

### ⚠️ Заведите для этого отдельный аккаунт

Весь автоматический трафик — от всех пользователей бота — пойдёт через один
аккаунт. Для Instagram он выглядит ровно так, как выглядит бот: запросы без
пауз, без просмотров ленты, без обычной человеческой активности. За это аккаунт
могут попросить пройти проверку, ограничить или заблокировать.

Поэтому заведите пустой аккаунт специально для бота. Основной использовать не
стоит: потерять рабочий аккаунт ради скачивания роликов — плохой размен.

### Как подключить

**Способ 1 — файл (работает везде, нужен на сервере).**

1. Поставьте расширение для экспорта cookies в формате **Netscape**
   (например, «Get cookies.txt»).
2. Залогиньтесь в браузере под аккаунтом для бота и откройте `instagram.com`.
3. Экспортируйте cookies **только для instagram.com** в файл `cookies.txt`
   и положите его в корень проекта.
4. Пропишите путь:

```env
COOKIES_FILE=cookies.txt
```

**Способ 2 — прямо из браузера** (только когда бот запущен на том же компьютере):

```env
COOKIES_FROM_BROWSER=firefox
```

Firefox удобнее: он хранит cookies в обычной базе. Chrome на macOS шифрует их
через Keychain, и при чтении система будет спрашивать разрешение.

Важная разница: этот способ отдаёт боту cookies **для всех сайтов**, куда он
обращается, — включая вашу сессию Google при скачивании с YouTube. Файл,
экспортированный только для `instagram.com`, ограничивает доступ одним сервисом.

При старте бот скажет, что увидел: сколько записей и для каких доменов. Значения
самих cookies в логи не попадают.

> 🔐 `cookies.txt` равносилен входу в аккаунт без пароля, и двухфакторная защита
> тут не помогает — она проверяется при входе, а пропуск уже выдан. Файл добавлен
> в `.gitignore`: не выкладывайте его в репозиторий и никому не передавайте.
>
> Cookies со временем протухают. Когда Instagram завершит сессию, бот снова
> начнёт отвечать «нужны cookies» — файл надо будет экспортировать заново.

## Доступ по заявке

Бот не раздаёт доступ всем подряд и не требует вписывать каждого в
настройки руками. Для незнакомого человека `/start` и есть заявка —
отдельной кнопки нет, чтобы не пришлось угадывать, отправилось
что-нибудь или нет:

```
👋 Привет, Вася!

Я скачиваю видео и фото из YouTube, Instagram и TikTok.

📨 Заявка на доступ отправлена владельцу бота.
Как он её рассмотрит — я сразу напишу сюда. Ждать в чате не нужно.

Ваш Telegram ID: 100200300
```

Владельцу приходит заявка с тем, что о человеке известно, и три кнопки:

```
📨 Новая заявка

Кто: Вася Пупкин (@vasya)
ID: 100200300

   [ ✅ Принять ]  [ ❌ Отклонить ]
          [ 👤 Профиль ]
```

«Профиль» открывает человека в Telegram — видно, кого пускаете. Решение
приходит ему ответом, и принятый сразу может пользоваться ботом:
список допущенных спрашивается на каждом событии, перезапускать бота не
нужно.

Пока заявка ждёт решения, бот так и отвечает — «заявка ждёт решения», —
а не зовёт нажать `/start` ещё раз. Отклонённый может отправить заявку
заново: `/start`.

Чтобы всё это работало, нужен хотя бы один администратор — он и
принимает заявки:

```env
ADMIN_IDS=ваш id
```

Этого достаточно: при запуске администраторы вносятся в список
допущенных сами. `ALLOWED_USER_IDS` остаётся для тех, кого нужно
допустить сразу, без заявки.

Список живёт в `access.db` рядом с ботом и переживает перезапуск.
Потерять его — значит потерять доступ всем, кроме администраторов,
поэтому в резервную копию он идёт первым.

**Если администратора нет вовсе**, бот ведёт себя по-старому: пустой
`ALLOWED_USER_IDS` означает «открыт для всех», заполненный — работает
как белый список. Принимать заявки в этом случае некому, и о них бот не
заговаривает.

Заявки, которые ждут решения, видны командой `/requests` — на случай,
если уведомление потерялось. Их число показывает и `/status`.

### Кого вы уже пустили

`/users` показывает всех допущенных — по карточке на человека, с
кнопками:

```
Вася Пупкин (@vasya)
ID: 100200300
Допущен: 2026-10-08 18:59

   [ ❌ Исключить ]  [ 🚫 Заблокировать ]
          [ 👤 Профиль ]
```

**Исключить** — человек уходит из списка и в следующий раз получит
приглашение подать заявку. Так убирают того, кто больше не нужен.

**Заблокировать** — бот перестаёт ему отвечать вовсе, и заявку он больше
не подаст. Для назойливых. Заблокированные идут в том же списке ниже, с
кнопкой «↩️ Разблокировать» — блокировка не тупик.

Ни о том, ни о другом человек не узнаёт отдельным сообщением: он просто
увидит приглашение подать заявку, когда снова напишет боту.

Администратора из списка убрать нельзя — доступ у него от `ADMIN_IDS`, и
запись в базе ничего не решает. Кнопок у его карточки нет.

## Если открываете бота для всех

Пустой `ALLOWED_USER_IDS` означает, что ботом может пользоваться любой, кто его
нашёл. Это рабочий режим, но вместе с ним появляется то, чего нет у домашнего
бота.

**Задайте суточный лимит.** Иначе один человек способен занять бота на весь
день — чаще не со зла, а просто увлёкшись:

```env
ALLOWED_USER_IDS=
DAILY_LIMIT_PER_USER=20
ADMIN_IDS=ваш id
```

Администраторы под лимит не подпадают. Счётчик живёт в памяти процесса и
обнуляется не только в полночь, но и при перезапуске бота — для небольшого
бота это приемлемо.

**Кого-то можно выгнать точечно**, не закрывая бота для остальных:

```env
BLOCKED_USER_IDS=123456789
```

**Все запросы идут с одного адреса.** Для YouTube, TikTok и Instagram весь
поток выглядит как активность одного клиента. Чем больше людей, тем выше шанс,
что сервис начнёт отвечать отказами — особенно если бот стоит на сервере,
который к тому же работает как VPN.

**Cookies предъявляются ваши.** Если они настроены, бот ходит в Instagram от
имени того аккаунта, чьи cookies ему дали, — за всех пользователей сразу. Чем
шире круг, тем быстрее к этому аккаунту появятся вопросы. Отдельный аккаунт
здесь обязателен, а не желателен.

**Трафик тоже ваш.** Каждый файл проходит через ваш сервер дважды: сначала
скачивается, потом отдаётся в Telegram.

## Когда сервис ломается не в коде бота

Иногда сервис перестаёт отдавать видео способом, который не чинится правкой
кода: у TikTok, например, при недоступности обычных страниц помогает
обращение к другому хосту API. Такие обходные пути задаются настройкой,
повторяющей ключ `--extractor-args` самого yt-dlp:

```env
EXTRACTOR_ARGS=tiktok:api_hostname=api22-normal-c-useast2a.tiktokv.com
```

Несколько сразу разделяются точкой с запятой, несколько значений одного
ключа — запятой:

```env
EXTRACTOR_ARGS=youtube:player_client=android,web;tiktok:app_version=35.1.3
```

Непонятные куски пропускаются с предупреждением в журнале: опечатка в
необязательном параметре не должна мешать боту запуститься.

Прежде чем подбирать такие параметры, стоит обновиться: `deploy/update.sh`
всегда подтягивает свежие `yt-dlp` и `gallery-dl`, а большинство поломок
лечится именно этим.

## Когда бот делит сервер с чем-то ещё

Сам по себе бот почти ничего не потребляет: пока никто не присылает ссылок, он
просто ждёт. Нагрузка появляется во время загрузок, и заметнее всего — на
канале, потому что каждый файл проходит через сервер дважды: сначала
скачивается, потом отдаётся в Telegram.

Если соседние службы стали работать медленнее, набор настроек для небольшого
сервера выглядит так:

```env
MAX_DOWNLOAD_RATE=5M
MAX_CONCURRENT_DOWNLOADS=2
```

Ограничение скорости действует и на видео, и на картинки: загрузки станут
дольше, зато перестанут забирать всю полосу.

Потолок качества `MAX_VIDEO_HEIGHT` трогать не советую. Он считается по высоте
кадра, а у вертикальных роликов — это почти весь Instagram и TikTok — высота
является длинной стороной, поэтому значение 720 превращает кадр 1080x1920 в
405x720. Для горизонтального видео потеря умеренная, для вертикального
заметная.

Кроме настроек, трафик экономят ещё три вещи, работающие сами:

- **фильтр по размеру при выборе формата.** Форматы, которые заведомо не влезут
  в лимит Telegram, отсеиваются до загрузки. Прежде бот качал файл целиком,
  убеждался, что тот не помещается, удалял его и качал заново ступенью ниже —
  один ролик мог проехать по каналу дважды;
- **предпочтение H.264.** Если такой формат есть, перекодирование не
  понадобится, а это самая тяжёлая для процессора часть работы. Когда
  перекодировать всё же приходится, ffmpeg ограничен двумя потоками и не
  занимает сервер целиком;
- **умеренная параллельность.** Куски файла качаются по два, а не по четыре:
  ровный поток для соседей по серверу лучше, чем рваные пики.

### Пауза и полная остановка

Перестать принимать загрузки, не трогая службу, — команда прямо в Telegram:

```
/pause     — новые загрузки не принимаются, владельцу бот по-прежнему доступен
/resume    — вернуться в работу
```

Это удобно с телефона и не требует SSH. Процесс остаётся запущенным, но
простаивающий бот ресурсов не занимает.

Полная остановка освобождает вообще всё:

```bash
sudo /opt/videobot/app/deploy/bot.sh stop     # выключить, в том числе после перезагрузки
sudo /opt/videobot/app/deploy/bot.sh start    # включить обратно
sudo /opt/videobot/app/deploy/bot.sh status   # что сейчас
sudo /opt/videobot/app/deploy/bot.sh logs     # живой журнал
```

## Статистика

Каждая загрузка попадает в SQLite: когда, кто, какой сервис, сколько весил
файл, сколько заняло времени и чем закончилось. Команда `/stats` показывает
сводку и доступна только тем, кто перечислен в `ADMIN_IDS`; в меню команд она
не значится, поэтому остальные о ней не узнают.

```
/stats          — за сегодня
/stats 7        — за неделю
/stats all      — за всё время
```

**Полные ссылки по умолчанию не сохраняются** — только домен сервиса, объём и
исход. Если учёт нужен подробнее, включается отдельно:

```env
STATS_STORE_URLS=true
```

Стоит понимать, что при этом у вас появляется журнал того, что именно смотрят
ваши пользователи. Для открытого бота это решение не только техническое.

### Сбои

Команда `/errors` показывает последние неудачи вместе с исходным текстом от
yt-dlp и список того, что повторяется чаще всего за неделю:

```
🧰 Сбои

Чаще всего за неделю
  12× ERROR: [TikTok] …: Unexpected response from webpage request
   2× ERROR: login required

Последние
10-06 19:07 · tiktok.com · video · id 100200300
  ExtractionFailed
  ERROR: [TikTok] …: Unexpected response from webpage request
```

Это и есть главная польза от сбора: пока человек один, сбой выглядит как
случайность, а когда одно и то же сообщение приходит от десяти разных людей,
сразу видно, что сломался сервис, а не ссылка. Хвост про «заведите issue на
GitHub» вырезается — он есть в каждом сообщении yt-dlp и ничего не добавляет.

Живое наблюдение остаётся за журналом службы:

```bash
sudo journalctl -u videodownloader -f | grep Загрузка
```

## Структура проекта

```
VideoDownloader/
├── bot/
│   ├── __main__.py          # точка входа: сборка Bot и Dispatcher
│   ├── config.py            # настройки из переменных окружения
│   ├── keyboards.py         # инлайн-кнопки и callback_data
│   ├── handlers/
│   │   ├── commands.py      # /start, /help, /id, /status
│   │   ├── download.py      # ссылка → выбор формата → отправка файла
│   │   └── errors.py        # перехват необработанных исключений
│   ├── middlewares/
│   │   ├── access.py        # белый список пользователей
│   │   └── throttling.py    # ограничение частоты запросов
│   ├── services/
│   │   ├── downloader.py    # обёртка над yt-dlp, лестница качества
│   │   ├── photos.py        # фотопосты через gallery-dl
│   │   ├── stats.py         # учёт загрузок в SQLite
│   │   └── links.py         # поиск ссылки и определение платформы
│   └── utils/
│       ├── cache.py         # короткие токены вместо длинных URL
│       └── format.py        # размеры, время, индикатор прогресса
├── tests/                   # 103 теста, без обращения к сети
├── Dockerfile
├── docker-compose.yml
└── .env.example
```

### Как это устроено

1. **Middleware** проверяет пользователя по белому списку и частоту запросов.
2. **`handlers/download.py`** находит ссылку в тексте и сразу запускает загрузку.
   Если у поста нет видеодорожки, он переключается на `services/photos.py`.
   Единственная оставшаяся кнопка — запасная «только звук», и под неё URL в
   `callback_data` не влезает (там всего 64 байта), поэтому в кнопку кладётся
   короткий токен, а ссылка живёт в кэше `utils/cache.py`.
3. **`services/downloader.py`** запускает yt-dlp. Он блокирующий, поэтому уходит в поток через
   `asyncio.to_thread`, а прогресс пишется в общий объект `Progress`.
4. Параллельно крутится задача, которая раз в 3.5 секунды обновляет сообщение с прогрессом.
5. Готовый файл отправляется с метаданными (длительность, размер кадра, обложка), после чего
   временный каталог удаляется.

## Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| `Ошибка конфигурации: Не задан BOT_TOKEN` | Нет файла `.env` или в нём пустой токен |
| В логах `ffmpeg не найден в PATH` | Установите ffmpeg — иначе не будет звука и MP3 |
| `⛔️ Нет доступа` | Ваш ID не в `ALLOWED_USER_IDS`. Узнайте его командой `/id` |
| «Сервис просит авторизацию» | Приватное видео или защита от ботов — нужны cookies |
| «Файл весит ~N МБ, а лимит 50 МБ» | Ролик слишком тяжёлый: возьмите аудио или поднимите свой Bot API server |
| Instagram совсем не работает | Без cookies он почти всегда закрыт — см. раздел выше |
| «Не нашлось ни видео, ни картинок» | Пост закрыт или это сторис. Для Instagram почти всегда нужны cookies |
| `could not find <браузер> cookies database` | Браузер не установлен или ни разу не запускался. Бот отключит этот источник и продолжит без cookies |
| Ошибки вида `Unable to extract` | Сервис поменял вёрстку. Обновите yt-dlp: `pip install -U yt-dlp` |
| TikTok: `Unexpected response from webpage request` | Не установлен `curl-cffi`. Без него yt-dlp не проходит проверку TikTok — см. раздел ниже |
| Видео играет как замерший кадр со звуком | Так Telegram показывает VP9 и AV1. Бот сам перекодирует такие ролики в H.264 — если симптом остался, проверьте, что ffmpeg на месте |
| «Не удалось скачать видео» без подробностей | Впишите свой ID в `ADMIN_IDS` — тогда бот покажет техническую причину прямо в чате |

Полезно при отладке:

```env
LOG_LEVEL=DEBUG
```
